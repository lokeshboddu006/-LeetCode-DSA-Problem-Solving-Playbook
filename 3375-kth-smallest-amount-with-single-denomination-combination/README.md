## 🧠 AI Explanation

### 💡 Intuition
To find the $k$-th smallest amount generated by any single coin denomination, we can reframe the problem into a counting question: *"For a given candidate amount `mx`, how many unique valid multiples are there $\le mx$?"*

Because the total count of valid multiples monotonically increases as `mx` increases, we can binary search for the minimum `mx` that yields at least $k$ valid amounts.

To count how many unique multiples exist up to `mx` across multiple coin denominations without double-counting (e.g., $6$ is a multiple of both $2$ and $3$), the code uses the **Principle of Inclusion-Exclusion (PIE)** over all non-empty subsets of `coins`.

---

### 🔍 Approach

1. **Binary Search Range (`findKthSmallest`)**:
   - `l` is initialized to `1` (minimum possible amount).
   - `r` is initialized to `1e11` ($10^{11}$), which serves as a safe upper bound since $k \le 2 \times 10^9$ and coin values are small ($\le 25$).
   - A standard binary search (`while (l < r)`) finds the lower bound:
     - `mid = (l + r) >> 1` calculates the midpoint.
     - `check(mid)` checks if the count of valid amounts $\le \text{mid}$ is $\ge k$.
     - If `check(mid)` returns `true`, the target amount is $\le \text{mid}$, so `r = mid`.
     - Otherwise, the target amount must be strictly greater, so `l = mid + 1`.

2. **Inclusion-Exclusion Counting (`check`)**:
   - Iterate through every non-empty subset of coins using a bitmask `i` from `1` to `(1 << n) - 1`.
   - For each bitmask `i`:
     - Determine which coins are included using `(i >> j & 1) == 1`.
     - Accumulate the Least Common Multiple (LCM) of all included coins into `v`.
     - If `v > mx` at any point, break out of the subset loop early (since `mx / v` would evaluate to `0`).
     - Calculate the size of the subset `m = Integer.bitCount(i)`.
     - Calculate how many multiples of `v` exist $\le mx$ via integer division `mx / v`.
     - If `m` is odd, add `mx / v` to `cnt` (inclusion).
     - If `m` is even, subtract `mx / v` from `cnt` (exclusion).
   - Return whether `cnt >= k`.

3. **Number Theory Helpers**:
   - `gcd(a, b)`: Implements Euclid's algorithm recursively to find the greatest common divisor.
   - `lcm(a, b)`: Computes the least common multiple using `a * b / gcd(a, b)`.

---

### 🧩 Algorithm

- **Binary Search Condition**: Find the smallest integer `mx` such that:
  $$\text{cnt}(mx) \ge k$$

- **Inclusion-Exclusion Principle (PIE)**:
  $$\text{cnt}(mx) = \sum_{S \subseteq \text{coins}, S \neq \emptyset} (-1)^{|S| - 1} \cdot \left\lfloor \frac{mx}{\text{lcm}(S)} \right\rfloor$$

- **GCD Recurrence**:
  $$\gcd(a, b) = \begin{cases} a & \text{if } b = 0 \\ \gcd(b, a \bmod b) & \text{otherwise} \end{cases}$$

---

### ✅ Why This Works

- **Monotonicity**: The number of valid multiples $\le mx$ is non-decreasing with respect to `mx`. This monotonicity makes binary search suitable to locate the exact $k$-th smallest value.
- **Correct Duplicate Handing**: Any number $x \le mx$ that is divisible by $p$ distinct chosen coins is counted $\binom{p}{1} - \binom{p}{2} + \binom{p}{3} - \dots = 1$ time under PIE, eliminating duplicates across different denominations.
- **LCM Property**: The set of numbers divisible by a set of coins is equivalent to the set of numbers divisible by their LCM.

---

### ⏱️ Complexity

- **Time Complexity**: 
  - **Binary Search**: $\mathcal{O}(\log(\text{MAX\_VAL}))$ iterations, where $\text{MAX\_VAL} = 10^{11}$.
  - **Subset Enumeration**: In each `check` call, there are $2^n - 1$ subsets. For each subset of length $n$, computing the LCM takes $\mathcal{O}(n \cdot \log(\min(\text{coins})))$.
  - **Total Time**: $\mathcal{O}(\log(\text{MAX\_VAL}) \cdot 2^n \cdot n \cdot \log(\text{max\_coin}))$.
  - With $n \le 15$, $2^{15} = 32,768$, so `check` executes at most $\approx 3.2 \times 10^4 \times 15$ operations per binary search step, comfortably within the execution time limit.

- **Space Complexity**:
  - $\mathcal{O}(1)$ auxiliary space beyond the recursion stack for `gcd`, which reaches a depth of at most $\mathcal{O}(\log(\text{max\_coin}))$.

### 🧠 DSA Pattern

- **Binary Search on Answer**
- **Bitmask Enumeration (Subsets)**
- **Inclusion-Exclusion Principle (PIE)**
- **Number Theory (GCD / LCM)**

---

### ⚠️ Common Mistakes

1. **Integer Overflow in LCM**: Multiplication `a * b` in `lcm` can easily overflow a 32-bit integer. The code correctly casts and uses `long` for `v`, `mx`, and intermediate results.
2. **Missing Pruning (`if (v > mx) break`)**: Without breaking early when `v > mx`, `a * b` could overflow even a 64-bit `long` if multiple LCM calculations are chained together.
3. **Upper Bound Selection**: Setting the binary search upper bound `r` too low (e.g., $2 \times 10^9$) would cause incorrect answers when $k = 2 \times 10^9$ and coin values are larger (up to $25$), as the answer can reach up to $5 \times 10^{10}$.

---

### 🚀 Optimization Notes

- **Early Termination in LCM**: The `if (v > mx) break;` check inside the bit scanning loop prunes invalid subset expansions early, avoiding unnecessary GCD calls.
- **Built-in Bit Count**: Using `Integer.bitCount(i)` computes the population count (number of set bits) using efficient hardware instructions.
