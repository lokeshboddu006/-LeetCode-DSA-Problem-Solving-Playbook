## 🧠 AI Explanation

### 💡 Intuition

The problem asks for the number of distinct non-empty subsequences of a string `s`.

The core observation behind this solution is that whenever we encounter a character `c`, we can attach `c` to the end of every distinct subsequence generated so far. Additionally, `c` itself can form a new single-character subsequence `"c"`. 

However, if `c` has appeared previously, appending `c` to subsequences that already ended with `c` will create duplicates. The solution tracks how many distinct subsequences currently end with each character (`d[j]`) and the total number of distinct subsequences formed so far (`a`). 

When processing character `c` (at index `j`):
- We can form `a + 1` potential subsequences ending in `c` (by appending `c` to all `a` existing subsequences, plus the single character `"c"`).
- We subtract `d[j]` (the subsequences ending in `c` created in previous steps) to exclude duplicate subsequences.
- The difference represents the net new distinct subsequences generated by this occurrence of `c`.

### 🔍 Approach

1. **Initialization**:
   - `m = 1e9 + 7`: The modulo value for large numbers.
   - `d`: An integer array of size 26 where `d[j]` stores the total number of distinct subsequences ending with character `(char)('a' + j)`.
   - `a`: Running total count of all distinct non-empty subsequences formed so far.

2. **Iterating Through the String**:
   - Loop through each character `s.charAt(i)` from index `0` to `s.length() - 1`.
   - Map the character to an alphabet index `j = s.charAt(i) - 'a'`.
   - Calculate `v`, the count of **new** distinct subsequences introduced by this character:
     `v = (a - d[j] + 1) % m`
   - Update `a` by adding `v` modulo `m`: `a = (a + v) % m`.
   - Update `d[j]` by adding `v` modulo `m`: `d[j] = (d[j] + v) % m`.

3. **Return Result**:
   - Return `(a + m) % m` to ensure the final result is non-negative modulo `10^9 + 7`.

### 🧩 Algorithm

The algorithm uses **Dynamic Programming** with state compression (running totals per character):

- **DP State**:
  - $a$: Total distinct non-empty subsequences formed from prefix $s[0 \dots i-1]$.
  - $d[j]$: Total distinct subsequences ending in character $j$ formed from prefix $s[0 \dots i-1]$.

- **Transitions for character $j = s[i] - 'a'$**:
  $$v = (a - d[j] + 1) \pmod{10^9 + 7}$$
  $$a_{new} = (a_{old} + v) \pmod{10^9 + 7}$$
  $$d[j]_{new} = (d[j]_{old} + v) \pmod{10^9 + 7}$$

### ✅ Why This Works

- **Uniqueness**: Subtracting $d[j]$ ensures that any subsequence ending in character $j$ that could already be formed by a previous occurrence of character $j$ is not counted twice.
- **Completeness**: Adding $a$ accounts for extending all existing distinct subsequences with the current character, and adding $1$ accounts for the new single-character subsequence consisting solely of the current character.
- **Correct Total**: By incrementally adding only the newly created unique subsequences $v$ to $a$, `a` accurately maintains the count of all distinct non-empty subsequences.

### ⏱️ Complexity

- **Time Complexity**: $\mathcal{O}(N)$, where $N$ is the length of string `s`. The solution iterates through the string once and performs $\mathcal{O}(1)$ arithmetic operations per character.
- **Space Complexity**: $\mathcal{O}(1)$ auxiliary space. Array `d` has a fixed size of 26 regardless of the input string length.

### 🧠 DSA Pattern

- **Dynamic Programming** (Linear DP with state compression / fixed array state)

### ⚠️ Common Mistakes

1. **Negative Modulo in Java**:
   In Java, the `%` operator retains the sign of the dividend. In `int v = (a - d[j] + 1) % m;`, if `a < d[j]` due to prior modulo wraparounds, `a - d[j] + 1` can be negative, leading to a negative `v`. While `return (a + m) % m;` attempts to handle negative numbers at the end, intermediate negative updates to `a` and `d[j]` can corrupt calculations in subsequent iterations.

2. **Forgetting the Single Character (+1)**:
   Omitting the `+ 1` in `(a - d[j] + 1)` would fail to account for the standalone single-character subsequence (e.g., `"a"` when encountering `'a'` for the first time).

### 🚀 Optimization Notes

- The time complexity $\mathcal{O}(N)$ and space complexity $\mathcal{O}(1)$ are already optimal.
- To avoid issues with negative modulo operations in Java, `v` can be calculated safely as:
  ```java
  int v = (a - d[j] + 1 + m) % m;
  ```
  Adding `m` guarantees that the value inside the modulo operation remains non-negative throughout all intermediate iterations.
